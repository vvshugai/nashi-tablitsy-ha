# Наши таблицы на Home Assistant OS

Raspberry Pi 4/5, 64 bit (`aarch64`), SSD. Дополнение имеет собственные данные и логины,
не запрашивает доступ к Supervisor, устройствам, Docker socket или конфигурации HA.

## Перенос

1. На Mac в папке проекта проверить `git log -1 --oneline`: нужен `b72cfbf` или более
   новый коммит main. Если версия старее, остановиться и сообщить разработчику.
   Ручной `git pull` не нужен: код доставляет автообновление. После проверки выполнить
   `./scripts/export-ha-migration.sh`.
   Он остановит сайт и автообновление, создаст согласованную копию базы, изображений,
   настроек и сертификатов. Оригиналы на Mac остаются. Архив содержит секреты, не публикуйте его.
2. Через дополнение Samba или SSH поместить `migration.tar.gz` в
   `/share/proxima-centauri/migration.tar.gz` на HA. Через Samba это папка `share/proxima-centauri`.
3. Установить дополнение. В настройках оставить `mode: migration`, указать имя Raspberry
   в `site_host` (обычно `homeassistant.local`) и при необходимости его IPv4 в `site_ip`.
4. Запустить. Первый старт проверит архив и SQLite и атомарно перенесёт его в собственный
   `/data/site`. Без архива и существующей базы запуск остановится, пустой сайт не создаётся.
   При последующих стартах архив не восстанавливается повторно.
5. Открыть `http://<IP-Raspberry>:8080`. Войти прежними логином и паролем. Проверить последние
   путешествия, игры, Bum Life и несколько изображений. Режим проверки отключает Telegram,
   автообогащение и ночные задачи. Обычные изменения сайта уже сохраняются на Raspberry.
6. После проверки установить `mode: active`, сохранить настройки и перезапустить дополнение.
   Сайт на Mac оставить остановленным. После проверки удалить архив из общей папки HA.
7. Настроить Tailscale на Raspberry по разделу ниже. Прежний внешний адрес ведёт на Mac
   и после его остановки сайт не откроет. Проверить новый адрес с телефона через мобильную
   сеть, затем указать его в `site_url` дополнения сайта и перезапустить сайт.

На тестовом запуске HA Mac уже остановлен: изменения не разойдутся между двумя базами.
Для возврата: остановить дополнение, на Mac выполнить `docker compose up -d`. Если на Raspberry
уже внесены изменения, сначала скачать свежую копию сайта: старая база на Mac их не содержит.

## HTTPS и доступ

HTTPS: `https://<site_host>:8443` или `https://<site_ip>:8443`. Порт можно изменить в разделе
«Сеть» дополнения. Порт 443 часто занят другими дополнениями, поэтому по умолчанию используется 8443.
Если перенесены `caddy-data` и `caddy-config`, прежний корневой сертификат сохраняется.
Иначе установить новый сертификат с `http://<IP-Raspberry>:8080/ca.crt`.
Старая иконка приложения на телефоне привязана к адресу Mac: после переезда открыть новый HTTPS-адрес
и добавить его на главный экран. Ingress не используется: у сайта свои защищённые страницы и вход.

## Доступ вне дома: Tailscale

Установить [Tailscale от Home Assistant Community Apps](https://github.com/hassio-addons/addon-tailscale).
Включить запуск при загрузке, войти по ссылке из журнала в тот же tailnet, где находятся телефоны.
При `userspace_networking: false` можно сразу проверить `http://<Tailscale-IP-Raspberry>:8080`.
Tailscale должен быть включён и на телефоне; домашний IP или `homeassistant.local` снаружи сами по себе не работают.

Для постоянного HTTPS-адреса настроить Tailscale Services (опция `services` текущего дополнения):

1. В консоли Tailscale включить MagicDNS и HTTPS Certificates в DNS.
2. В Access controls создать тэг, например `tag:tablitsy`, разрешив своему аккаунту его назначать.
   В настройках дополнения Tailscale добавить его в `advertise_tags`.
3. В разделе Services консоли создать сервис `svc:tablitsy` с HTTPS-портом 443.
   У аккаунтов Влада и Ани должен быть доступ к этому сервису по правилам tailnet.
4. В дополнении Tailscale добавить в `services` (остальные настройки сохранить):

   ```yaml
   services:
     - name: svc:tablitsy
       target: http://127.0.0.1:8080
       protocol: https
       port: 443
   ```

   Дополнение Tailscale использует сеть хоста: `127.0.0.1:8080` здесь ведёт на опубликованный
   порт сайта на Raspberry. Если порт сайта изменён в «Сеть», изменить и `target`.
   `share_homeassistant` обслуживает сам HA на 8123, для сайта его включать не нужно.
5. Перезапустить Tailscale, в Services консоли одобрить Raspberry как хост сервиса.
   Открыть HTTPS-адрес сервиса, показанный консолью, с телефона при выключенном Wi-Fi.
   Проверить также после перезапуска дополнения Tailscale и при выключенном Mac.

Это доступ внутри tailnet. Funnel и проброс портов роутера не нужны.
Если в установленной версии Tailscale нет `services`, сначала обновить это дополнение.

## Адрес в Telegram

В настройке **`site_url`** дополнения сайта указать проверенный адрес, например
`https://tablitsy.<ваш-tailnet>.ts.net` (точный адрес взять из консоли Tailscale), сохранить
и перезапустить сайт. Для использования только дома допустим `https://homeassistant.local:8443`.
Адрес задаётся без пути, параметров и пароля. Он используется для ссылок в напоминаниях
и уведомлениях; настройка не создаёт VPN или прокси сама.

Старый `SITE_URL` из Mac `.env` автоматически не применяется, чтобы ссылки не вели на
остановленный Mac. Пустой `site_url` оставляет уведомления без ссылок.
Нужны установочный пакет и образ с этой настройкой; исходная сборка `b72cfbf` её ещё не содержит.

## Обновления и резервные копии

GitHub собирает образ сразу после зелёной «Проверки» main (и раз в 30 минут как запасной путь),
если изменилось приложение. Собираются ARM64 и AMD64, Raspberry только скачивает образ.
Дополнение в режиме `active` раз в 5 минут просит Supervisor перечитать каталог и, если есть
новая версия, обновляет себя само (`auto_update`, по умолчанию включено; нужен доступ
`hassio_role: manager`). От слияния в main до сайта обычно 10-15 минут.
Каталог дополнений получает новую версию, если настроены `HA_ADDON_REPOSITORY` и
`HA_ADDON_REPOSITORY_TOKEN` в GitHub. Установленное дополнение обновляется штатно через HA;
автоматическую установку можно включить в карточке дополнения, если она доступна в вашей версии HA.
Без отдельного каталога новая версия ставится из свежего установочного пакета, см. docs/HOME-ASSISTANT.md.
Обновление заменяет контейнер; `/data/site` с базой, файлами, сертификатами и ключами сохраняется.
Ночные копии сайта хранятся внутри дополнения. Включите дополнение в резервную копию HA:
на время такой копии сайт останавливается для согласованности SQLite. Дубликаты ночных копий
исключены, рабочая база, оригиналы изображений, сертификаты и настройки включены.


Выпуски HA не запускаются на каждый коммит. Планировщик объединяет изменения за полчаса;
документация проекта, тесты, данные и вспомогательные скрипты сами по себе не пересобирают
образ. Сравниваются файлы с последней успешной публикацией, поэтому не теряются изменения
после неудачной сборки. Ручной запуск выпуска доступен в любое время. При потере кэша
GitHub безопасно пересоберёт образ.
Ежедневная чистка GHCR сохраняет последние пять выпусков, latest, вручную закреплённые
тэги и все версии моложе семи дней. Сохраняются также вложенные манифесты ARM64/AMD64
и attestations: безымянные версии нельзя удалять без проверки этих зависимостей.
При ошибке чтения registry удаление отменяется. За один запуск удаляется не более
100 устаревших версий. База на HA, резервные копии и приватность образа не меняются.
